# 학교알리미 학교 링크 설계

## 목표

사이드바와 모바일 상단에 표시되는 현재 학교 버튼에서 해당 학교의 학교알리미 페이지를 바로 열 수 있게 한다. 학교 변경 기능은 설정 화면에서 계속 사용할 수 있어야 한다.

## 사용자 흐름

1. 사용자가 학교 검색 결과에서 학교를 선택한다.
2. 학교 검색 결과에 학교알리미 식별자 또는 상세 URL이 포함되면 프로필의 학교 정보와 함께 저장한다.
3. 사이드바/모바일의 학교명 버튼을 누르면 저장된 학교알리미 상세 URL을 새 탭으로 연다.
4. 학교알리미 상세 식별자를 확보하지 못한 경우 학교명 검색 URL을 새 탭으로 열어 잘못된 상세 페이지를 만들지 않는다.
5. 학교를 변경하려면 설정 화면의 학교 검색 영역을 사용한다.

## 데이터 설계

학교 객체에 선택적 필드를 추가한다.

- `schoolInfoId`: 학교알리미 상세 페이지의 `SHL_IDF_CD`
- `schoolInfoUrl`: 검증된 상세 URL 또는 검색 fallback URL

기존 NEIS 필드(`ATPT_OFCDC_SC_CODE`, `SD_SCHUL_CODE`)와 기존 프로필은 그대로 호환한다. 신규 필드가 없는 기존 저장 데이터도 정상 동작해야 한다.

## API/서비스 설계

학교알리미 OpenAPI 키는 서버 환경 변수로만 사용한다. 브라우저 코드에 키를 포함하지 않고 `/api/schoolinfo` 프록시를 추가한다. 프록시는 학교명·지역·주소·NEIS 학교코드 조합으로 검색하고, 결과에서 정확히 일치하는 학교의 `SHL_IDF_CD`를 반환한다. 일치 결과가 없으면 `schoolInfoUrl`을 학교알리미 검색 URL로 생성한다.

검색 결과에 식별자를 붙이는 과정이 실패해도 NEIS 학교 선택은 성공해야 하며, 상세 링크만 검색 fallback으로 동작한다.

## UI 설계

- 학교명 버튼은 외부 링크(`<a target="_blank" rel="noopener noreferrer">`)로 렌더링한다.
- 접근성 라벨에 “학교알리미 새 탭에서 열기”를 포함한다.
- 학교 변경 동작은 설정 화면의 학교 선택 영역으로 유지한다.
- 학교알리미 URL이 없는 기존/예외 데이터는 학교알리미 검색 URL을 사용한다.

## 오류 처리

- API 키 미설정, 네트워크 오류, 식별자 미확인: NEIS 검색을 막지 않고 학교알리미 검색 fallback을 사용한다.
- 외부 링크 생성 시 학교명은 URLSearchParams로 인코딩한다.
- 프로필 저장/마이그레이션은 기존 필드를 보존하고 선택 필드만 추가한다.

## 테스트 및 검증

- 학교 검색 결과 정규화가 학교알리미 필드를 보존하는지 테스트한다.
- 학교알리미 상세 URL과 검색 fallback URL 생성 규칙을 테스트한다.
- 기존 학교 검색/프로필 저장 테스트가 계속 통과하는지 확인한다.
- 렌더링 결과에서 학교명 링크의 `target`, `rel`, `href`를 확인한다.
