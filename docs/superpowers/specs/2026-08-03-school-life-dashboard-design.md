# 학교생활 대시보드 개편 설계

## 목표

현재의 학교 정보 조회 서비스를 초·중·고등학교용 반응형 일일 대시보드로 바꾼다. 학생·학부모·교사가 앱의 설정 방식을 먼저 익히지 않아도, 지금 필요한 학교 정보를 바로 찾을 수 있어야 한다.

## 범위와 사용자

이번 개편에서 서비스 대상은 **초등학교·중학교·고등학교**다. 기존 NEIS의 학교 검색·학사 일정·급식 정보를 그대로 사용하고, 학교급에 맞는 시간표 API를 선택한다.

- **학생:** 다음 수업, 오늘 급식, 다가오는 학사 일정을 본다.
- **학부모:** 자녀의 학년·반, 급식과 알레르기 정보, 다가오는 학사 일정을 본다.
- **교사:** 선택한 학급의 시간표와 오늘의 학사 일정을 본다.

로그인, 서버 프로필, 권한 관리, 다자녀 관리는 이번 범위에 넣지 않는다. 역할·학교·학년반·알레르기 정보는 현재처럼 해당 기기에 저장한다.

## 서비스 구조

### 처음 사용하는 사람의 설정 흐름

현재의 빈 시작 화면 대신 짧은 설정 흐름을 제공한다.

1. 역할을 고른다: 학생, 학부모, 교사.
2. 학교를 검색해 선택한다. 검색 결과에는 학교급을 표시한다.
3. 선택한 학교급에 맞는 학년과 반을 설정한다. 학부모에게는 자녀 학급, 교사에게는 조회할 학급이라는 표현을 쓴다.
4. 급식 알레르기는 선택적으로 설정한다. 건너뛰고 나중에 설정할 수 있다.
5. 설정 완료 안내 후 홈 대시보드로 이동한다.

처음 쓰는 사람에게 실제 학교명이나 6학년 1반을 미리 표시하지 않는다. 설정을 마치기 전에는 실제 학교 정보를 보여주지 않는다.

### 학교급별 시간표 규칙

학교 검색 결과의 `SCHUL_KND_SC_NM`을 저장해 시간표 조회에 사용한다.

| 학교급 | 시간표 API | 학년 선택 |
| --- | --- | --- |
| 초등학교 | `elsTimetable` | 1~6학년 |
| 중학교 | `misTimetable` | 1~3학년 |
| 고등학교 | `hisTimetable` | 1~3학년 |

학교급을 판별할 수 없거나 지원하지 않는 학교는 시간표를 조회하기 전에 이유를 설명한다. 학사 일정과 급식은 학교급과 관계없이 계속 제공한다.

### 탐색 구조

화면 크기와 관계없이 홈, 일정, 시간표, 급식, 내 설정의 다섯 메뉴를 유지한다.

- **PC:** 왼쪽 사이드 메뉴를 사용한다. 내 설정에서 역할·학교·학년반·알레르기를 모두 바꾼다.
- **모바일:** 하단 고정 메뉴를 사용한다. 상단에는 선택한 학교명과 내 설정 진입만 둔다.
- 기능별 설정 탭은 없앤다. 설정은 항상 내 설정 한 곳에서 찾을 수 있어야 한다.
- 일정은 목록과 달력을 선택형 보기로 제공한다. 시간표는 날짜별과 주간 보기를 선택한다. 날짜를 쓰는 모든 화면에는 현재 선택 날짜와 오늘 버튼을 같은 위치에 둔다.

## 홈 대시보드의 정보 우선순위

역할마다 먼저 보여주는 카드는 다르지만, 사용하는 데이터와 카드 디자인은 통일한다.

| 역할 | 첫 카드 | 두 번째 카드 | 보조 카드 |
| --- | --- | --- | --- |
| 학생 | 다음 수업 또는 오늘 시간표 | 오늘 급식 | 다가오는 일정 |
| 학부모 | 자녀 학급과 오늘 시간표 | 알레르기 경고를 포함한 급식 | 다가오는 일정 |
| 교사 | 선택한 학급 시간표 | 오늘의 학사 일정 | 다가오는 일정 |

카드 하나에는 행동 하나만 둔다. 시간표 열기, 급식 열기, 일정 열기처럼 명확하게 연결한다. 홈에는 전체 달력, 긴 목록, 설정 폼을 넣지 않는다.

## 반응형 화면 기준

### PC: 1920 × 1080 기준

콘텐츠 최대 너비는 1440px, 바깥 여백은 48px로 둔다. 화면은 세 열로 구성한다.

```text
┌────────────── 최대 1440px 콘텐츠 영역 ──────────────────────────────┐
│ 왼쪽 메뉴 │ 오늘 요약과 핵심 카드 │ 다가오는 일정과 안내          │
│ 220px     │ 유동 너비              │ 320px                         │
└─────────────────────────────────────────────────────────────────────┘
```

왼쪽 메뉴는 항상 보이게 한다. 가운데에는 역할에 따른 핵심 정보를, 오른쪽에는 가까운 일정과 짧은 안내를 둔다. 1920px 전체 너비로 카드가 과도하게 늘어나지 않게 한다.

### 태블릿: 768~1199px

왼쪽 메뉴는 상단 메뉴 또는 서랍 메뉴로 접는다. 여유가 있으면 두 열 카드, 부족하면 한 열 카드로 바꾼다. 모든 기능은 유지한다.

### 모바일: 360~767px

한 열의 오늘 중심 화면을 사용한다. 다가오는 일정 전에 우선순위가 높은 카드 두 개를 먼저 보여준다. 하단 메뉴를 고정하고, 모든 터치 대상은 최소 44px로 만든다. 일정과 급식은 날짜별 목록을 기본으로 보이고, 주간표·달력은 보조 보기로 제공한다. 페이지 전체의 가로 스크롤은 만들지 않는다.

## 시각 디자인 방향

참고 디자인은 정보 위계와 절제된 사용감만 참고하고, 스타벅스의 브랜드 요소는 사용하지 않는다.

### 디자인 토큰

| 이름 | 값 | 사용처 |
| --- | --- | --- |
| 배경 | `#F4F1EA` | 따뜻한 전체 배경 |
| 기본 녹색 | `#006241` | 제목, 선택된 메뉴, 핵심 맥락 |
| 행동 녹색 | `#00754A` | 주요 버튼과 상호작용 상태 |
| 짙은 녹색 | `#1E3932` | PC 왼쪽 메뉴, 중요한 정보 영역 |
| 연한 민트 | `#D4E9E2` | 선택·저장 완료 상태 |
| 카드 | `#FFFFFF` | 카드와 모달 |
| 기본 글자 | `rgba(0,0,0,.87)` | 본문 |
| 보조 글자 | `rgba(0,0,0,.58)` | 설명과 부가 정보 |
| 경고 | `#C82014` | 알레르기 경고와 위험한 오류에만 사용 |
| 중요 일정 금색 | `#CBA258` | 중요한 학사 일정에만 제한적으로 사용 |

글꼴은 **Pretendard** 하나로 통일한다. PC 섹션 제목은 24px/600, 모바일 섹션 제목은 20px/600, 본문은 16px/400, 버튼은 14px/600, 부가 정보는 13px/400을 기준으로 한다. 제목에만 읽기 좋은 범위에서 좁은 자간(`-0.01em`)을 적용한다.

카드는 12px 모서리와 아주 옅은 2단 그림자를 사용한다. 주요 버튼은 높이 48~50px의 알약 형태로 만든다. 장식용 그라데이션, 이모지 단독 아이콘, 과도하게 큰 카드, 무거운 그림자는 사용하지 않는다. 아이콘은 항상 이해 가능한 텍스트와 함께 쓴다.

## 상호작용과 문구 원칙

- 모든 조작 요소는 `button`, `a`, `input`, `select` 같은 의미 있는 HTML 요소로 만들고 키보드 포커스를 분명히 보여준다.
- 학교 검색 결과에는 학교명, 학교급, 교육청 지역, 주소를 보여 동명 학교를 구분하게 한다.
- 정보 없음과 조회 실패는 원인과 다음 행동을 함께 안내한다. 예: “이 날짜의 시간표가 아직 등록되지 않았습니다. 학년·반을 확인하세요.”와 학년·반 바꾸기 버튼.
- 빈 학교 검색어에는 아무 반응이 없는 대신 입력 안내를 표시한다.
- 학년·반은 저장 전에 검증하며, 잘못된 값을 임의로 1반으로 바꾸지 않는다.
- 알레르기 경고는 NEIS 급식표 표기 기준의 참고 정보이며, 안전을 위해 학교에도 확인해야 함을 알린다.
- 화면 문구는 같은 표현을 계속 사용한다. 예를 들어 설정 저장 버튼을 누른 뒤에는 항상 “설정을 저장했어요”라고 안내하고, 학년·반 바꾸기는 언제나 학년·반 설정 화면으로 이동한다.

## 기술 방향

기존 서버 측 `/api/neis` 프록시와 기기 저장 방식을 유지한다. 프록시의 허용 API 목록에 `misTimetable`, `hisTimetable`을 추가하고, 클라이언트는 저장된 학교급으로 적절한 시간표 API를 선택한다. 새 정보 구조를 유지하기 어렵지 않게, 필요한 범위에서만 하나의 `index.html`에 모인 화면·상태·API·스타일 코드를 역할별 파일로 나눈다. Pretendard 로딩 외에 새로운 제품 의존성은 추가하지 않는다.

## 완료 기준

1. 처음 방문한 사용자는 역할·학교·학년반을 설정한 뒤에만 학교 정보를 본다.
2. 초·중·고등학교는 학교급에 맞는 시간표 API와 학년 선택 범위를 사용한다.
3. 학생·학부모·교사는 같은 핵심 서비스를 유지하면서 각자에게 맞는 홈 대시보드를 본다.
4. 1920×1080에서는 최대 1440px의 세 열 구조를 사용하고, 모바일에서는 하단 메뉴를 가진 터치 친화적 한 열 화면으로 바뀐다.
5. 역할·학교·학년반·알레르기는 내 설정 한 곳에서 바꿀 수 있다.
6. 날짜를 쓰는 모든 화면에는 선택 날짜와 오늘 버튼이 분명히 있다.
7. 동명 학교, 정보 없음, 요청 실패, 미설정 상태에서 무슨 일인지와 다음 행동을 안내한다.
8. 모든 상호작용 UI는 키보드 탐색, 보이는 포커스, 의미 있는 HTML 요소를 지원한다.
